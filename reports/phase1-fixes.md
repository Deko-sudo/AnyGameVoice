Исходная Фаза 1 и три доработки вошли в один локальный коммит `2ae8d0c7206ed0c05d0f68a78111c6c592b58db2` поверх `9c2727a`. Всего в коммите девять файлов. Включён уже подготовленный `pyproject.toml` с точкой входа `agv`. Автор и коммитер — `Codex <codex@localhost>`, как в предыдущих коммитах.

## Блокировка игры

`.agv-manifests/.<game>.lock` хранит JSON с PID, временем начала в UTC и именем хоста. Мёртвый PID, чужой хост, повреждённый JSON или старый пустой каталог блокировки приводят к перехвату с предупреждением. Живой PID на том же хосте блокирует новую операцию и отображается вместе со временем начала. При завершении удаляется только запись того же владельца. Функция `lock_info(path)` возвращает метаданные или `None`. Отдельная короткая блокировка `.lock-guard` сериализует проверку и замену метаданных. ОС освобождает её при завершении процесса.

На POSIX liveness проверяется через `os.kill(pid, 0)`. Для Windows предусмотрена проверка через `ctypes` и Win32 API. Интеграционный прогон выполнялся на Linux. Windows-ветка остаётся без проверки на нативной системе.

## Управление манифестами

- `agv manifests list` выводит ID, дату создания, путь игры, возраст в днях и счётчики всех четырёх статусов. Без записей команда завершается с кодом 0 и пустым выводом.
- По умолчанию команды смотрят в `.agv-manifests` текущей папки. `--game PATH` у обеих команд определяет каталог по родителю игры и фильтрует записи по самой игре.
- `agv manifests prune` удаляет только манифесты, у которых все записи имеют статус `uninstalled`. `--older-than 30d` добавляет порог по `created_at`. `--dry-run` показывает пути без удаления. Перед фактическим удалением состояние повторно проверяется под блокировкой игры.

В README описаны снятие модов в обратном порядке, расположение копий и манифеста, действия при конфликте, устаревшей блокировке и недостающей копии. Снятие мода сохраняет отчёт для повторных проверок. Его очистка выполняется отдельной командой `prune`. [Инструкция в README](../README.md#uninstalling-a-mod)
