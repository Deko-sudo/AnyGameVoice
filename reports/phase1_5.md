# Phase 1.5 — подготовка ручного сеанса Ren’Py

**Помощник готов к ручному прогону.** Файловые операции проверены на временной копии эталонной сцены. Проверка в реальной игре требует человека и Ren’Py SDK.

## Что создано

| Файл | Назначение |
|---|---|
| `scripts/phase1_5_smoke.sh` | Bash-точка входа для подготовки, установки, снятия и сверки. |
| `scripts/phase1_5_smoke.py` | Вызывает CLI из текущего checkout, сопоставляет отчёт генерации с репликами, сохраняет журнал и сравнивает SHA-256. |

## Команды

Из корня AnyGameVoice запустить помощник на чистой копии. Для Piper требуется модель. По умолчанию используется провайдер Ollama. Параметр `--provider` позволяет выбрать другой настроенный провайдер, а `AGV_PYTHON` указывает интерпретатор при необходимости.

```bash
bash scripts/phase1_5_smoke.sh --game "/path/to/game" --output "/path/to/smoke-output" \
  --target es --engine piper --voice "/path/to/model.onnx"
```

Внутри используются позиционные пути в `agv scan GAME` и `agv mod GAME --out OUTPUT --translate-to LANG`. Подкоманды `install` и `uninstall` получают аргументы `--game`, `--output`, `--map` и `--manifest` по существующему CLI. Установка сопоставленных WAV возможна при `done` и `partial`. При `partial` причины пишутся в `phase1_5.log`. В пустом каталоге вывода появятся `report.json`, `dialogue.srt`, `phase1_5.log` и `phase1_5_state.json`. Последний хранит путь к манифесту и исходные SHA-256 файлов в `game/voice/`.

После игры закрыть SDK и скопировать напечатанную помощником команду снятия.

```bash
bash scripts/phase1_5_smoke.sh --uninstall "/path/to/.agv-manifests/install-id.json"
```

Помощник проверяет отчёт CLI, сверяет SHA-256 восстановленных файлов с манифестом и сравнивает весь исходный перечень обычных файлов `game/voice/` при наличии связанного состояния. Правильное восстановление печатает `OK`. Сбой снятия, конфликт, пропуск или расхождение хеша дают список проблем и код 1.

## Ручной запуск

Человек запускает исходную игру, проходит обе ветки после установки и сопоставляет звук с `dialogue.srt` рядом с WAV. После снятия мода человек снова запускает игру и слушает 2–3 реплики. Проверка слышимости, момента воспроизведения, визуальных сбоев, падений и качества перевода остаётся частью ручного сеанса. [Чеклист](../docs/phase1_5-checklist.md) · [Шаблон](../docs/phase1_5-report-template.md)

## Found, not fixed

- Существующий Ren’Py-парсер возвращает реплики и номера строк. В нём нет связи с директивами `voice`. Помощник использует этот парсер для проверки реплики и добавляет консервативную привязку к буквальной директиве на предыдущей значимой строке с тем же отступом.
- Сопоставление ограничено исходниками `game/*.rpy` и существующими WAV внутри `game/voice/`. Динамические имена, расширенный синтаксис `voice`, автоголос, архивы `.rpa`, сцены только в `.rpyc`, симлинки, общие WAV в нескольких распознанных директивах и оригиналы в других аудиоформатах могут остаться без замены. Оставшиеся успешные строки генерации перечисляются в логе как несопоставленные. Если пар нет, установка завершается до изменения игры.
- Установка заменяет звук по пути оригинала. Текст в Ren’Py остаётся исходным, переведённые субтитры находятся в отдельном SRT. Без подходящего файла состояния при снятии доступна сверка по манифесту для установленных файлов.

## Проверки подготовки

- `bash -n scripts/phase1_5_smoke.sh` и `--help` прошли.
- На эталонной сцене с подставными переводчиком и TTS получено `done` с 27 WAV, установлен один `beacon.wav`. Снятие вернуло исходные байты и `OK`. Повторное снятие также прошло.
- При ошибке синтеза одной строки получено `partial` с 26 WAV. Причина ошибки записалась в журнал, однозначная замена установилась. После ручной правки файла снятие вывело один конфликт и завершилось с кодом 1. Изменённый файл сохранился.
- При повторном использовании одного WAV в двух директивах помощник пропустил общий файл и остановил установку. Отдельная проверка выявила лишний файл в `game/voice/` после побайтного восстановления оригинала.
- `python -B -m pytest -q -p no:cacheprovider tests` — **107 passed, 1 warning**. Предупреждение выдал существующий HTTP-тест Starlette о поддержке httpx. Прогоны выполнены в Bubblewrap с исходниками только для чтения, отдельным `/tmp` и изолированной сетью.
